# Часть 1. archive_logs.sh

## Запуск

```
sudo bash archive_logs.sh               # папка /LOGS, порог 90%
sudo bash archive_logs.sh /LOGS 85      # своя папка и свой порог
```

Автоматически каждые 5 минут через cron:

```
sudo cp archive_logs.sh /usr/local/bin/
sudo chmod +x /usr/local/bin/archive_logs.sh
echo "*/5 * * * * root /usr/local/bin/archive_logs.sh >> /var/log/archive_logs.log 2>&1" | sudo tee /etc/cron.d/archive_logs
```

| Кусок cron-строки | Что значит |
|---|---|
| `*/5 * * * *` | минута (каждая 5-я), час, день, месяц, день недели (любые) |
| `root` | от какого пользователя запускать |
| `>> /var/log/archive_logs.log` | дописывать вывод в файл |
| `2>&1` | ошибки (поток 2) писать туда же, куда обычный вывод (поток 1) |
| `sudo tee файл` | записать текст в файл с правами root |

Коды выхода: 0 - всё хорошо, 1 - ошибка (неверные аргументы, раздел не смонтирован, tar не смог создать архив).

## Общий смысл

1. Строки 11-35: проверки. Папка есть, порог - число от 1 до 100, раздел смонтирован. Иначе выход с кодом 1.
2. Строки 39-55: сколько занято на разделе. Если не больше 90% - выход, ничего не делаем.
3. Строки 122-136: для каждой из трёх папок считаем размер. Если больше трети лимита - вызываем `archive_folder`.
4. Строки 59-120, функция `archive_folder`: берём логи от старых к новым, пока не освободим нужный объём, самый новый не трогаем. Пакуем в `archive/<компонента>_archive_<дата>.tar.gz`, и только если tar успешен - удаляем исходники.

Пример на числах. Раздел вмещает 1000 МБ.
- Общий лимит: 1000 * 90 / 100 = 900 МБ. Занято 920 МБ, значит превышен.
- Лимит одной папки: 900 / 3 = 300 МБ.
- auth_service занимает 500 МБ, это больше 300 - архивируем. data и system меньше 300 - не трогаем.
- Цель для auth: 300 * 80 / 100 = 240 МБ. Освободить нужно 500 - 240 = 260 МБ.
- Берём самые старые файлы, пока их сумма не станет 260 МБ или больше.

Строка 11: `if [ -n "$1" ]; then`

Строка 18: `if [ ! -d "$LOGS_DIR" ]` - `!` "не", `-d` "это существующая папка".

Строка 23: `if ! echo "$THRESHOLD" | grep -q '^[1-9][0-9]*$'; then`

| Токен | Что делает |
|---|---|
| `echo` | вывести значение |
| `\|` | пайп: вывод слева отдать на вход команде справа |
| `grep -q` | искать по шаблону, ничего не печатать, только код: 0 нашлось, 1 нет |

Ноль впереди запрещён, потому что bash считает `010` восьмеричным числом, то есть 8.

Строка 27: `-lt` меньше, `-gt` больше, `||` или. Обычные `<` `>` внутри `[ ]` нельзя: там это перенаправление в файл.

Строка 32: `mountpoint -q "$LOGS_DIR"` - код 0, если к папке подключён раздел. `-q` - ничего не печатать.

Строка 37: `$(команда)` - выполнить команду и подставить её вывод. `date '+%Y-%m-%d %H:%M:%S'` - дата и время в формате год-месяц-день часы:минуты:секунды.

Строка 39: `df_line=$(df -P -k "$LOGS_DIR" | tail -n 1)`

| Токен | Что делает |
|---|---|
| `df` | информация о разделе, на котором лежит папка |
| `-P` | каждая запись в одну строку (без переносов длинных имён) |
| `-k` | размеры в килобайтах |
| `tail -n 1` | взять последнюю строку (первая - заголовок) |

Вывод df выглядит так: `/dev/sdb1  91840  78884  5788  94%  /LOGS` - устройство, размер, занято, свободно, процент, точка монтирования.

| Токен | Что делает |

| `cut -d ' '` | резать строку по пробелу (-d, delimiter) |

Строки 45-47: деление в bash целочисленное, дробная часть отбрасывается (`7 / 2` = 3).

Строка 52: `-le` - меньше или равно. Превышение - это строго больше.

Строка 59: `archive_folder() {` ... `}` - объявление функции. Скобки всегда пустые, аргументы внутри функции - это `$1`, `$2` того вызова (строка 134 передаёт имя компоненты).

Строка 63: `du -s -k "$dir" | cut -f 1`

| Токен | Что делает |
|---|---|
| `du` | сколько места занимает папка или файл |
| `-s` | одно число на всю папку (summary), без подпапок по отдельности |
| `-k` | в килобайтах |
| `cut -f 1` | взять первую колонку; du разделяет колонки табуляцией, а её cut режет по умолчанию |

Строки 68-72: `for file in "$dir"/*.log; do`
- `*.log` - bash подставляет все файлы с концом `.log`, отсортированные по алфавиту.
- Если файлов нет, в `file` попадёт сам текст `.../*.log`. Поэтому `[ -f "$file" ]` проверяет, что это настоящий файл.
- Этот цикл только считает логи: нужно знать номер последнего, самого нового.

Строки 77-91: выбор файлов.
- `continue` - перейти к следующему шагу цикла, `break` - выйти из цикла.
- Строка 82: если дошли до последнего файла (номер = количество), выходим: самый новый не берём.
- Строка 85: если уже освободили достаточно, выходим.
- Строка 88: `du -k "$file"` - размер одного файла.
- Строка 90: `files_to_archive="$files_to_archive $(basename "$file")"` - дописать к строке пробел и имя файла. `basename` отрезает путь: `/LOGS/auth_service/a.log` превращается в `a.log`.

Строка 93: `-z` - строка пустая (противоположность `-n`). `return` - выйти из функции (а `exit` - из всего скрипта).

Строка 101: `${component}` - то же, что `$component`. Фигурные скобки нужны, потому что сразу после имени идёт `_archive`, и без скобок bash искал бы переменную `component_archive`.

Строка 103: `tar -czf "$dir/archive/$archive_name" -C "$dir" $files_to_archive`

| Токен | Что делает |
|---|---|
| `-c` | создать архив (create) |
| `-z` | сжать через gzip |
| `-f имя` | имя файла архива (file) |
| `-C папка` | перед упаковкой зайти в папку, чтобы в архиве были только имена файлов, без полного пути |
| `$files_to_archive` | без кавычек специально: bash разрежет строку по пробелам, и каждый файл станет отдельным аргументом tar |

Строка 104: `$?` - код возврата последней команды (здесь tar). `-ne 0` - не равно нулю, то есть ошибка.

Строка 105: `rm -f` - удалить, `-f` (force) - не ругаться, если файла нет.

Строка 112: `for name in $files_to_archive` - цикл по именам из строки, разделённым пробелами.

Строка 138: `exit $had_errors` - выход с кодом 0 или 1, смотря были ли ошибки tar.

## Вопросы

Почему не трогаем самый новый файл? В него сейчас пишет компонента. Удалим его - она продолжит писать в удалённый файл, и логи потеряются.

Почему файлы идут от старых к новым без сортировки? Имя: `компонента_YYYY_MM_DD_timestamp.log`. Год, месяц, день, время - слева направо, от крупного к мелкому, поэтому алфавитный порядок совпадает со временем.

Почему удаляем только после tar? Если архив не создался (кончилось место), исходники должны остаться, иначе логи пропадут совсем.

Что делаем, если tar упал? Удаляем недописанный архив (строка 105), исходники не трогаем, в конце выходим с кодом 1.

Почему чистим до 80% лимита, а не до 100%? Иначе папка остаётся у самой границы, через 5 минут снова чуть больше лимита, и архивация запускается каждый раз ради одного файла.

Где gzip? Ключ `-z` у tar: tar сам сжимает через gzip.

Почему 100% - это "занято + свободно"? ext4 держит 5% в резерве для root. Если делить на полный размер, скрипт видит 85%, когда df показывает 94%, и срабатывает слишком поздно, когда компоненты уже не могут писать.

Зачем проверка mountpoint? Если раздел не подключился, /LOGS - обычная папка на системном диске. df покажет размер системного диска, и скрипт решит, что всё в порядке. Поэтому выходим с ошибкой.

Раздел заполнен на 92%, но ни одна папка не больше трети? Значит место занято чем-то ещё. По ТЗ архивируем только папки, превысившие свою треть, поэтому ничего не трогаем.

Зачем отдельная папка archive? Чтобы архивы не путались с логами. Скрипт берёт только `*.log`, архив второй раз не упакует.

Архивы ведь тоже копятся? Да, удалять их ТЗ не требует. Логи - текст, gzip сжимает его примерно в 10 раз. Порог 90% оставляет место, куда писать архив. Удаление старых архивов - возможное улучшение.

# Часть 2. mount_logs.sh и logs-mount.service

## Запуск

Подготовка флешки или второго диска (один раз):

```
lsblk                              # список дисков, найти флешку, например sdb
sudo fdisk /dev/sdb                # создать раздел: n, p, 1, Enter, Enter, w
sudo mkfs.ext4 -L LOGS /dev/sdb1   # отформатировать в ext4 с меткой LOGS
```

Установка службы:

```
sudo cp mount_logs.sh /usr/local/bin/
sudo chmod +x /usr/local/bin/mount_logs.sh
sudo cp logs-mount.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable logs-mount.service
sudo systemctl start logs-mount.service
systemctl status logs-mount.service
df -h /LOGS
```

| Команда | Что делает |
|---|---|
| `chmod +x` | разрешить запуск файла как программы |
| `daemon-reload` | systemd перечитывает файлы служб, чтобы увидеть новую |
| `enable` | запускать службу при каждой загрузке |
| `start` | запустить прямо сейчас |
| `status` | показать, запускалась ли служба и что она вывела |
| `df -h /LOGS` | убедиться, что /LOGS - это флешка (`-h` - размеры в МБ/ГБ) |

Проверка пункта 2: `sudo reboot`, после загрузки снова `df -h /LOGS`.

## Общий смысл

Раздел - кусок диска своего размера. Флешка обычно один раздел целиком. В Linux нет букв дисков, есть одно дерево папок. Чтобы файлы попадали на флешку, её раздел подключают (монтируют) к папке: `mount /dev/sdb1 /LOGS`. После этого всё, что пишется в /LOGS, физически ложится на флешку. Если логи переполнят раздел, встанет только он, а системный диск продолжит работать.

`/dev/sdb1`: `/dev/` - папка, где Linux показывает устройства в виде файлов; `sd` - диск; `b` - второй по счёту (`a` - системный); `1` - первый раздел на нём.

mount_logs.sh:
1. Строки 7-10: если /LOGS уже смонтирован - выходим, второй раз не нужно.
2. Строки 12-27: ищем раздел по метке LOGS, до 10 попыток раз в секунду. Не нашли - ошибка.
3. Строки 29-38: создаём папку /LOGS, если её нет, и монтируем.
4. Строки 40-45: создаём папки трёх компонент, если их нет.

Служба нужна для пункта 2 ТЗ: монтирование при запуске системы. Сам скрипт сам не запустится, его при каждой загрузке запускает systemd. Без службы после перезагрузки /LOGS был бы обычной пустой папкой.

Строка 14: `while [ $attempt -le 10 ]; do` ... `done` - повторять, пока attempt меньше или равно 10.

| `[Install]` | раздел, когда включать |
| `WantedBy=multi-user.target` | запускать при обычной загрузке системы; работает после `systemctl enable` |

## Вопросы

Зачем служба? Пункт 2 ТЗ: монтирование при запуске системы. systemd при каждой загрузке запускает mount_logs.sh.

Почему ищем по метке, а не пишем /dev/sdb1? Имя устройства может поменяться: вставили ещё одну флешку - и наша стала sdc. Метка LOGS задаётся при форматировании и не меняется.

Зачем 10 попыток? При загрузке флешка определяется не сразу, скрипт может запуститься раньше неё.

Что если уже смонтирован? Выход с кодом 0: это не ошибка, всё уже готово. Скрипт можно запускать сколько угодно раз.

Что если флешки нет? Ошибка и код 1, служба в статусе failed. Скрипт архивации тоже откажется работать: проверит mountpoint.

Почему не через /etc/fstab? ТЗ просит именно скрипт для монтирования, интегрированный с запуском ОС.

# Часть 3. test_archive_logs.sh

## Запуск

```
sudo bash test_archive_logs.sh
```

Лежит рядом с archive_logs.sh. Нужен root (sudo): тест подключает раздел через mount. В конце строка `Пройдено тестов: 8 из 8`, код 0. Если хоть один тест упал - код 1, и под упавшим тестом печатается, что не так и что вывел основной скрипт.

## Общий смысл

Проблема: на обычной папке df покажет размер всего диска, и 90% не наберётся никогда. Поэтому тест создаёт настоящий маленький раздел:
1. Строки 33-35: файл из нулей на 100 МБ, форматирование в ext4, подключение как диска (`mount -o loop`).
2. Строки 41-46: вместимость считается так же, как в основном скрипте. Один лог = 1% вместимости, чтобы сценарии описывать в процентах. Лимит папки тест считает сам: 90% / 3.
3. Каждый тест: очистить раздел, создать логи по сценарию, запустить основной скрипт, проверить результат.
4. Строки 280-287: отключить раздел, удалить всё, напечатать итог.

Тест не верит выводу основного скрипта, а сам пересчитывает: сколько логов осталось, сколько архивов, что внутри архива, что ушли самые старые, что новейший на месте, что папка стала меньше лимита, какой код выхода.

| Тест | Состояние до | Ожидаем |
|---|---|---|
| 1 | auth 50%, data 10%, system 10% (всего 70%) | ничего не трогаем, хотя auth больше трети |
| 2 | auth 52%, data 25%, system 15% (92%) | архивируется только auth |
| 3 | auth 40%, data 40%, system 12% (92%) | архивируются auth и data |
| 4 | по 29% в каждой + чужой файл 6% (93%) | порог превышен, но ни одна папка не больше трети: ничего |
| 5 | в auth один файл на 45% | это текущий файл, не трогаем |
| 6 | порог abc, 150, 010, несуществующая папка | код 1, ничего не трогаем |
| 7 | папка не смонтирована | код 1, "не смонтирован" |
| 8 | логи auth не сжимаются, архив не влезает | код 1, логи на месте, недописанного архива нет |

## Разбор сложных строк

| `of=` | куда писать (output file) |
| `bs=1M` | размер блока 1 МБ |
| `count=100` | 100 блоков, итого 100 МБ |
| `2>/dev/null` | сообщения dd (поток ошибок 2) выбросить; `/dev/null` - "чёрная дыра" |

Строка 34: `mkfs.ext4 -q` - отформатировать файл в ext4, `-q` - без лишнего вывода.

Строка 35: `mount -o loop` - подключить файл так, как будто это диск (`-o` - опции, `loop` - файл в роли устройства).

Строки 54-56: имя лога. `timestamp` - Unix-время (секунды с 1970 года), у i-го файла на i часов больше. `date -d "@$timestamp" '+%Y_%m_%d'` - перевести Unix-время в дату (`-d` - взять эту дату вместо текущей, `@` - число это Unix-время). `${component}_${day}_...` - скобки, чтобы bash не принял `_` за часть имени переменной.

Строка 71: `dd if="$data_source" ... bs=1K count="$size_kb"` - создать файл нужного размера в КБ.

Строка 81: `ls "$1" | grep -c '\.log$'` - `-c` - вывести количество совпавших строк. `\.` - именно точка (без `\` точка в шаблоне означает "любой символ").

Строка 93: `bash "$SCRIPT" "$@" > "$OUTPUT" 2>&1`

| Токен | Что делает |
|---|---|
| `"$@"` | все аргументы функции, каждый отдельно |
| `> файл` | обычный вывод записать в файл |
| `2>&1` | ошибки туда же |

Строка 94: `exit_code=$?` - запомнить код выхода основного скрипта.

Строка 109: `grep -q "$text" "$OUTPUT"` - есть ли такая строка в выводе основного скрипта.

Строка 136: `ls .../*.tar.gz | head -n 1` - имя первого архива (`head -n 1` - первая строка).

Строка 137: `tar -tzf архив` - показать список файлов в архиве (`-t` - list, `-z` - gzip, `-f` - файл).

Строки 140-149: как проверить, что ушли именно самые старые. Если заархивировано N файлов, то файл номер N должен исчезнуть, а файл номер N+1 остаться. Вместе с подсчётом это значит, что ушли ровно файлы 1..N - самые старые.

Строки 177-179: `while read line; do ... done < "$OUTPUT"` - читать файл построчно: `read` берёт одну строку, `< файл` подаёт файл на вход циклу.

Строка 222: чужой файл в корне раздела - занимает место, но не принадлежит ни одной компоненте.

Строка 269: `/dev/urandom` - случайные байты, gzip почти не может их сжать. Архив получается почти такого же размера, как логи, и не помещается в свободное место.

## Вопросы

Почему не тестировать на обычной папке? df покажет размер всего диска (например, 1 ТБ), порог 90% не наберётся, архивация не запустится ни в одном тесте.

Зачем root? mount и umount работают только от root.

Почему тест не верит выводу скрипта? Скрипт может напечатать "заархивировано", а на деле ничего не сделать. Тест сам пересчитывает файлы, архивы и размеры.

Почему в тестах 1 файл = 1%? Так сценарии легко описать: "auth 52%" - это 52 файла. Числа не зависят от того, сколько места ext4 заняла под служебные данные.

Как понять, что тесты вообще что-то ловят? Ломаем основной скрипт и смотрим, какой тест упадёт:

| Поломка в archive_logs.sh | Упадёт |
|---|---|
| убрать проверку общего порога 90% (строка 52) | тест 1 |
| делить лимит на 2 вместо 3 (строка 46) | тесты 2, 3, 5 |
| не защищать самый новый файл (строка 82) | тест 5 |
| не удалять файлы после tar (строка 113) | тесты 2, 3 |
| считать проценты от полного размера с резервом (строка 43) | тесты 2, 3, 4, 5 |
| убрать проверку mountpoint (строка 32) | тест 7 |
| всегда exit 0 (строка 138) | тест 8 |
| не удалять недописанный архив (строка 105) | тест 8 |
| разрешить ноль впереди в пороге (строка 23) | тест 6 |

Все эти поломки проверены запуском.
